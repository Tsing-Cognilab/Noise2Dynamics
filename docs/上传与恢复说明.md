## Git 与大文件分开

代码、配置、协议、JSON/JSONL 结果、日志、XML 状态和紧凑媒体进 Git。模型、HDF5/NPZ/NPY 数据和压缩资源进入 **各自仓库的 Release 附件**；个人附件私有，公司附件公开。不把完整的 154 GB 归档上传。第三方许可证和下载来源均保留，代码许可证不等于所有外部数据和权重的统一商用许可。

普通 Git 拒绝超过 100 MiB 的单文件，因此不能直接 `git add` 整个原项目。这里不启用 Git LFS，不改订阅、不设置付费额度。

三个大文件包按需拆成 128 MiB 的分块：

- `cvm-datasets.tar.zst.part001` 等：示范数据和训练/验证缓存；
- `cvm-models.tar.zst.part001` 等：冻结策略、各个 CVM 模型和对照权重；
- `cvm-resources.tar.zst` 或其分块：压缩的第三方源代码与媒体资源；
- `release-manifest.json`：每个包、分块的大小与 SHA256；
- `SHA256SUMS`：上传文件的校验清单。

包和分块均在服务器整理目录的 `artifacts/` 下，被 `.gitignore` 排除。`manifests/binary_assets.jsonl` 记录还原后的相对路径、大小及 SHA256。未上传完成时不能把“整理完成”当作“GitHub 已保存”。

## 第一步：服务器 CLI 登录

ChatGPT 的 GitHub 连接与服务器上的 GitHub CLI 是两条独立连接。前者能查看账号和操作已有仓库；当前连接没有新建仓库或上传 Release 二进制附件的接口，所以实际长时间上传使用官方 GitHub CLI。

在你已登录的服务器终端运行：

```bash
cd /data/lizhenhao/lizhenhao/Noise2Dynamics_CVM
python3 tools/bootstrap_gh.py --login
```

脚本只把校验过 SHA256 的官方 Linux amd64 GitHub CLI 下载到 `tools/.runtime/`，不需要 sudo，也不改系统包或其他项目。CLI 会给出网页地址和一次性设备码；在本地已登录 GitHub 的浏览器完成确认，账号必须是 `Audience2Li`。不要把访问令牌或设备码发到聊天里。

这一步由你确认授权。GitHub CLI 的凭据可能保存在服务器个人目录的 `~/.config/gh`（若没有可用系统密钥环，可能为明文配置）；仅应在你信任的服务器个人账号中登录。整理目录、Git 和 Release 均不会包含该凭据。若不希望服务器保留登录，上传结束后运行 `tools/.runtime/gh auth logout --hostname github.com --user Audience2Li`，它只移除服务器 CLI 的登录，不移除 ChatGPT 连接。

## 第二步：创建仓库与上传

登录后，在服务器运行下面的长命令：

```bash
tmux new-session -s cvm_github_upload_v2 'bash /data/lizhenhao/lizhenhao/Noise2Dynamics_CVM/tools/start_upload.sh'
```

脚本会按顺序完成：

1. 核对账号为 `Audience2Li`，验证所有源代码、实验文件和上传分块的 SHA256。
2. 分别核对个人仓库私有、公司仓库公开、账号有 push 权限。只有个人仓库不存在时才会新建私有仓库；公司仓库必须已存在。上传器不自动修改任何可见性。
3. 提交新的 CVM 专用 Git 历史，不带旧项目历史。提交署名使用 GitHub 的 noreply 邮箱，不使用私人邮箱。
4. 非强制推送 `main`，个人 remote 为 `origin`，公司为 `company`；已有不相容历史时停止，不做 reset、不做 force push。
5. 从 Release 列表查找匹配标签，包括草稿；找到后全程用 Release ID 查询。旧版错误使用仅查询已发布版本的 tag 接口，已经修正。已有草稿复用，不删除或重复创建。
6. 两个仓库分别逐块上传并核对 SHA256，已校验分块跳过。没有服务器摘要时通过流式下载再验证一次。
7. 每个仓库都在全部附件成功后才发布 Release。分别写 `UPLOAD_COMPLETE_Audience2Li.json`、`UPLOAD_COMPLETE_Tsing-Cognilab.json`，两个都存在才代表双目标都完成。兼容旧的 `UPLOAD_COMPLETE.json` 只代表个人备份，不代表公司完成。

如果更喜欢先网页创建，可以在 `https://github.com/new` 选 owner `Audience2Li`、名称 `Noise2Dynamics`、**Private**，不要勾选 README、gitignore 和许可证初始化选项。然后再运行上面的命令。已有非空仓库时脚本会停止供检查，不会覆盖内容。

`tmux` 脱离按 `Ctrl+B` 再按 `D`。重连查看：

```bash
tmux attach -t cvm_github_upload_v2
```

## 中断后如何继续

这是**分块级断点续传**，不是每一个 HTTP 请求内部从某个字节继续。已完成且校验通过的分块不重新上传；正在上传但尚未完成的那个分块会重传，最大约 128 MiB。若发现同名但大小/摘要不符的附件，脚本停止，不自动删除或覆盖远端材料。

如果终端仍留在原来的 tmux 会话，直接重跑：

```bash
cd /data/lizhenhao/lizhenhao/Noise2Dynamics_CVM
set -o pipefail
python3 -u tools/publish.py --target both 2>&1 | tee -a upload-dual.log
```

不要重新准备另一份混合项目，不要清理 `artifacts/`。两份进度分别保存在 `upload-progress-Audience2Li.json` 和 `upload-progress-Tsing-Cognilab.json`，同名分块不能混用两个仓库的上传进度。Git 推送重跑也是非强制推送；不保证单次 Git push 的字节级续传。

若只想单独继续一个仓库，用 `python3 -u tools/publish.py --target personal` 或 `--target company`。`--target both --check` 仅核对本地 SHA256、账号、两个仓库权限和已有 Release，不上传，不修改 GitHub。默认不带 `--target` 仍只处理个人仓库，避免误公开。

## 如何确认真的完成

最终必须同时满足：

- 日志先后出现个人 `(PRIVATE)` 和公司 `(PUBLIC)` 两条 `COMPLETE`，最后出现 `ALL TARGETS COMPLETE`；
- 两个带 owner 名的 `UPLOAD_COMPLETE_*.json` 都存在，记录对应提交号和 Release ID；
- 网页个人标记 Private，公司公开，两者 `main` 都有 README/六组代码/对应结果；
- 两个 Release `cvm-assets-20261013` 都有全部分块和校验文件。

`PREPARATION.json` 只表示服务器整理；它的 `uploaded: false` 不会被改成误导性的远端完成标记，实际上传完成单独看 `UPLOAD_COMPLETE.json`。

## 新机器恢复

先克隆私有仓库，下载上述 Release 的所有附件至仓库外一个空目录。Linux 需要 `git`、`python3`、`zstd`。在克隆后的仓库里运行：

```bash
python3 tools/restore_assets.py --assets-dir /absolute/path/to/downloaded_release_assets
```

还原工具验证每个分块和完整包的 SHA256，拒绝未知文件、路径穿越、链接成员及覆写已有不同内容的文件；已有相同内容的文件会核对后保留。恢复中断可重跑。二进制文件会回到原来的仓库相对位置，不进入 Git。

环境不是靠 Git clone 自动恢复。`task_restore_v1/Dockerfile` 依赖原来已有的 `noise2dynamics:franka-v1` 基础镜像，不能声称从空机器直接 build 就完全可用。CVM 环境身份在 `docs/ENVIRONMENT.json`；原 Docker 镜像保存在另一个完整归档里。本仓库不包含那些旧基础镜像和整份归档。

一些原结果锁、录像任务保留绝对路径 `/data/lizhenhao/lizhenhao/n2d_dreamerv3`。精确回放应在全新 Linux 环境复现这个路径；不要把恢复命令覆盖到现有项目，不要为搬家静默修改实验记录和源码指纹。

## 文件清单

`manifests/files.jsonl` 是保留源文件的逐项 SHA256 清单；`binary_assets.jsonl` 是独立资产清单；`excluded.jsonl` 记录选定目录内跳过的缓存、锁、残缺下载和重复计划；`PREPARATION.json` 给出大小和范围。只允许白名单的六组源代码与结果进入快照，其余顶层旧项目文件不扫描、不复制。

安全检查会阻止发现的私钥格式、GitHub token、AWS access-key ID 等典型凭据。原目录仍应保持私人访问；自动扫描不能代替对所有文本的人工审查。第三方许可证原样保留，私有仓库不替第三方数据或权重添加新的授权。
